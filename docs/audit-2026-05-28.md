## 3. Needs owner decision (config / product gaps — not bugs)

1. **No explicit "Reject" / "Request changes" on the customer bid viewer.** The
   customer's `ContractManagement` BidViewer offers **Accept & pay** and **Ask for
   appointment** only. There is no first-class *decline* or *request-changes*
   action — the customer's only "no" path is to ask for an appointment. Confirm
   whether a decline/counter action is wanted before go-live.
2. **New-bid notification is in-app only.** The customer learns about a new bid
   via the blinking "Contract management" badge when they're on `/room`. There is
   **no email/SMS push** on a new bid. If customers should be notified out-of-band,
   we need: notification channel keys (SendGrid for email — already wired for the
   morning brief; Twilio for SMS — not wired), and a trigger on `submit_project_bid`.
3. **T&C is a placeholder.** `/legal/contracting-terms` is a stub page. Legal must
   supply the real General T&C document before any contract is billable.
4. **Zoom `assigned → live` leg is untestable in this harness.** Closing 2.B's
   final chat-unlock leg needs a real Zoom join (two humans or a Zoom SDK test
   hook). Env already present for Zoom edge functions; this is a test-harness
   limitation, not a missing config.

## 4. Systemic issues

1. **Overlay components don't all use design tokens / the z-index ladder.**
   `EngineerIncomingMatch` (D2) hard-codes hex colors, an `rgba()` scrim, and a
   bare `z-50`. The Part 1 brief calls for a single documented z-index ladder
   (toast > modal > popover > drawer > base) with every arbitrary z-index replaced
   by a token. A repo-wide grep for raw `z-[` / `z-50` / `rgba(` / `#`-hex in
   overlay components is warranted — this is almost certainly not the only one.
   (Full sweep pending under Part 1.)
2. **Realtime + poll belt-and-suspenders is consistent and works.** Both verified
   surfaces (supervisor roster, engineer ring) pair a Supabase realtime channel
   with a short polling fallback, so a dropped event doesn't strand the actor.
   This is a good pattern; the 2.G channel enumeration will confirm it holds
   everywhere (and that channels are cleaned up on unmount).
